## 输出规则

- 首先给出 5–10 行摘要，再给完整 Brief；
- 区分“用户已确认”“从项目证据推断”“暂定默认值”；
- 对阻塞性开放问题不要假装已解决；
- 验收标准必须能被截图比较、交互测试、内容检查或代码测试验证；
- 用户只要求实现提示词时，可从 Brief 生成，但不得丢失状态、响应式、可访问性与审美校准；
- 只有多页面、设计系统、重设计或跨 Agent 迭代需要时，才根据 `design-md-template.md` 追加 `DESIGN.md`。
