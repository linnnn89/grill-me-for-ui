# Visual Critique

实施后的默认视觉验证协议。它确认视觉呈现和机械 UI 边界；复杂 Operate 或多步骤流程按需追加任务走查。任务走查验证用户可见的交互连续性，不替代权限逻辑、数据写入与失败恢复的功能测试。

## 1. 证据

尽量一次准备：

- 真实内容；
- 主要桌面、移动和长截图；
- 默认、加载、空、错误、成功、无权限和交互状态；
- 原始 UI Brief / Art Direction Card；
- 重设计的前后对照；
- 对比度、溢出、Focus、资源和性能检查。

没有截图、交互或等价证据时，只能输出静态评审，不能声称视觉已验证。

### 证据获取与对齐

使用当前环境中能够打开目标表面的工具，不把具体浏览器、MCP 或 CLI 名称写成固定依赖。每份证据记录：

- 来源设计或设计契约；
- 实际渲染表面；
- 路由、视口、主题、内容、权限和交互状态；
- 截图、录屏、DOM、可访问性树或等价证据；
- 无法获取或无法对齐的部分。

接受证据前先检查它确实显示目标窗口、目标状态和完整区域。比较前对齐内容、视口与状态；证据不等价时先说明差异，不进行虚假的像素级判断。

## 2. 两轮预算

```text
Pass 1：批量发现
→ 一个 Fix batch
→ Pass 2：确认 P0/P1 与回归
→ 停止
```

所有截图、扫描、微调和重构都计入预算。Pass 2 仍有阻塞问题时如实报告并请求新范围，不自动继续。

## 3. Pass 1 短检查

按宏观到微观一次检查：

1. **五秒印象**：产品、主要结果、第一锚点和三个气质词是否清楚；
2. **构图**：缩略后仍有主次、视线流、密疏节奏和坚定边缘；
3. **品牌指纹**：隐藏 Logo 后仍有至少三个识别点，且不只来自颜色或圆角；
4. **视觉系统**：Type、Color、Form、Material、Imagery、Motion 来自同一方向；
5. **产品真相**：前后对照确认核心产品含义、功能线索和平台行为没有丢失；
6. **真实边界**：长内容、空值、错误、权限、200% 放大和素材失败不会崩溃；
7. **响应式**：移动端重新编排核心任务，而非机械单列；
8. **机械检查**：对比度、Label、alt、Focus、溢出、点击目标、资源、reduced motion 和性能。

只有用户明确要求深度 Critique，或短检查发现 P0/P1 但无法定位根因时，才读取 `visual-critique-deep.md`。

## 4. 任务走查，按需

Surface 为 Operate、存在多步骤流程，或交互连续性属于验收标准时，使用 UI Brief 中的主要任务进行一次短走查：

1. 用户能否从预期入口发现下一步；
2. 当前对象、范围和状态是否可理解；
3. 操作前能否预期结果，操作后能否确认结果；
4. Pending、失败、无权限、中断和返回是否保留约定上下文；
5. 可逆操作能否恢复，不可逆操作是否在执行前表达影响；
6. 适用的键盘、触控和辅助技术路径是否仍能完成任务。

记录真实完成的步骤、观察到的反馈和未覆盖边界。后端正确性、真实权限执行和数据持久化仍使用独立功能证据。

## 5. 分级与修复

- **P0 方向**：Surface、Art Direction、锚点或素材前提错误，或新版本丢失关键产品真相与平台行为；
- **P1 结构**：层级、构图、系统、响应式或关键无障碍错误；
- **P2 完成度**：排版、间距、对齐、图标、阴影、动效或局部状态；
- **P3 偏好**：不影响任务、系统和方向，默认不改。

把所有发现合并为一个 Fix batch，先 P0、再 P1、最后集中处理必要 P2。P0 需要新方向时停止局部修复并请求授权。

每项记录：

```text
问题 / 级别：
证据：
影响：
修复动作：
代价：
验证方式：
```

## 6. Pass 2

只确认：

- P0/P1 已关闭；
- 没有新回归；
- 主要视口和关键状态通过；
- 适用时，主要任务走查中的 P0/P1 已关闭；
- Art Direction 与品牌指纹仍成立；
- 已执行的机械检查通过。

通过后停止。剩余 P2/P3 作为非阻塞项。
