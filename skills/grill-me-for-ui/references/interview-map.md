# UI Interview Map

本文件帮助 Agent 选择下一条最有价值的问题分支。它不是要按顺序念完的问卷。

## 使用原则

- 先解决上游决策，再进入下游细节。
- 只询问会改变设计或验收结果的事项。
- 如果已有代码、截图或文档能回答，先检查证据。
- 每次只选择一个尚未解决的节点。
- 一个分支确认后，记录它对后续节点的约束。

## 0. 任务分类

先判断当前任务最接近哪种类型：

| 类型 | 优先分支 | 常见风险 |
|---|---|---|
| 新产品或多页面应用 | 用户、范围、页面地图、导航、设计系统 | 过早进入视觉细节 |
| 单页面新设计 | 主要任务、内容层级、布局、状态 | 页面漂亮但任务不清 |
| 现有 UI 重设计 | 保留项、痛点、证据、迁移边界 | 功能回归或只换皮 |
| Dashboard / 后台 | 数据任务、筛选、密度、表格、详情 | 卡片堆砌、信息不可扫读 |
| 落地页 / 官网 | 受众、承诺、CTA、证据、转化路径 | 视觉抢过核心信息 |
| 表单 / 多步流程 | 输入、验证、保存、恢复、完成状态 | 只设计正常提交 |
| 内容 / 文档页 | 阅读、目录、搜索、长内容和锚点 | 宽度和层级失控 |
| 独立组件 | 使用场景、变体、内容边界、状态 | 组件不可复用或状态缺失 |

## 1. 问题、用户与主要结果

### 必须得到的答案

- 谁是主要用户；
- 用户进入界面时要完成什么；
- 最重要的一个结果或动作；
- 当前方案失败在哪里，或新方案为什么需要存在。

### 可用问题

- 用户完成这页后，最重要的变化是什么？
- 如果只能保留一个主要动作，应该是哪一个？
- 这是给新手、熟练用户，还是两者都要兼顾？
- 当前最影响使用的，是找不到入口、看不懂信息、操作太慢，还是不信任结果？

### 依赖

没有明确主要任务前，不决定布局和 CTA 强度。

## 2. 范围、非目标与成功标准

### 必须得到的答案

- 本次包含哪些页面、流程或组件；
- 哪些功能明确不改；
- 是否允许改变信息架构、交互和视觉；
- 怎样判断重设计有效。

### 可用问题

- 本次只解决当前页面，还是允许调整前后页面的流程？
- 现有功能中哪些必须原样保留？
- 最重要的成功标准是完成率、速度、错误率、理解度、转化率还是主观质感？
- 若时间不足，哪些内容可以推迟？

## 3. 内容、数据与信息层级

### 必须得到的答案

- 页面必须展示的内容；
- 用户第一眼、第二眼和按需查看的信息；
- 数据量、长度和更新频率；
- 内容是否允许编辑、筛选、比较或导出。

### 可用问题

- 用户第一眼必须看到哪一项信息？
- 哪些信息可以折叠、放到详情页或 Drawer？
- 页面面对的是几条数据、几十条还是上万条？
- 用户更常扫描、比较、搜索，还是逐条阅读？
- 标题、名称或翻译后文字最长可能到什么程度？

### 典型方向

- 少量同类对象：Card / List；
- 多字段比较：Table；
- 单个对象详情：Descriptions / sections；
- 核心指标概览：Statistic，但不能代替完整数据；
- 大量次级内容：Tabs、Collapse 或分层导航。

## 4. 页面地图、导航与核心流程

### 必须得到的答案

- 用户从哪里进入；
- 完成任务需要经过哪些页面或状态；
- 主导航与局部导航如何分工；
- 成功、失败和返回路径。

### 可用问题

- 用户通常从首页、搜索结果、通知还是外部链接进入？
- 这项任务应该在一页内完成，还是拆成步骤？
- 用户中断后，下次需要从哪里继续？
- 返回上一级时，筛选、滚动位置和未保存内容是否保留？
- 深层页面是否需要 Breadcrumb？

### 导航判断

- 少量顶级区域：Top Nav / Navbar；
- 功能多且需要频繁切换：Sidebar；
- 长内容单页：Anchor / sticky TOC；
- 明确顺序流程：Steps；
- 大量结果：Pagination 或虚拟滚动，由数据规模决定。

## 5. 布局与响应式结构

### 必须得到的答案

- 页面主布局；
- 内容最大宽度和密度；
- 桌面与移动端的优先级；
- 小屏下哪些内容重排、折叠或延后。

### 可用问题

- 这页更像操作工作台、阅读页，还是营销页面？
- 用户需要同时看到导航、列表和详情吗？
- 宽屏是利用空间展示更多信息，还是保持窄栏提高阅读性？
- 手机端最核心的一个动作是什么？
- 桌面表格在手机上应横向滚动、转卡片、减少列，还是进入详情？

### 常见布局

- Top Nav：公开站点或顶级栏目较少；
- Sidebar：后台、工具和高频多模块切换；
- Single Page：线性叙事或简单营销页；
- Doc Layout：长文档、目录和页面内导航；
- Card Grid：同类对象浏览；
- Centered Column：阅读、写作和简单表单。

## 6. 组件与交互选择

### 判断顺序

1. 用户要完成的动作；
2. 数据和内容结构；
3. 状态与错误恢复；
4. 最后才是组件名称和外观。

### 可用问题

- 这是立即生效的设置，还是需要统一保存？
- 选项是互斥、可多选，还是从大量候选中搜索？
- 查看详情时需要保留列表上下文吗？
- 删除或提交是否可撤销？
- 次级信息是悬停解释、点击展开，还是永久可见？

### 典型映射

- 二元立即生效：Switch；
- 互斥少量选项：Radio / Segmented；
- 多选：Checkbox；
- 大量候选：Select / AutoComplete；
- 保留背景上下文的详情：Drawer；
- 阻塞性短任务：Modal；
- 邻近轻量确认：Popconfirm；
- 非阻塞结果反馈：Toast；
- 持续重要信息：Alert。

## 7. 状态与恢复

### 对每个关键动作检查

- 初始状态；
- 加载状态；
- 空状态；
- 局部加载和部分失败；
- 输入验证；
- 网络失败和重试；
- 成功反馈；
- 无权限、只读和禁用；
- 破坏性操作确认、撤销或恢复；
- 重复点击和并发提交；
- 离开页面时的未保存内容。

### 可用问题

- 用户等待超过一秒时，需要看到进度、Skeleton 还是局部占位？
- 没有数据时，用户下一步应该做什么？
- 保存失败后，输入内容是否必须保留？
- 成功后是留在原地、显示 Result、进入详情还是返回列表？
- 删除是不可逆、软删除还是支持撤销？

## 8. 视觉语言

### 将形容词转为规则

不要停在“现代、简洁、高级”。继续明确：

- 信息密度：紧凑 / 平衡 / 宽松；
- 排版：功能型无衬线 / 编辑型衬线搭配 / 品牌字体；
- 层级：字号、字重、颜色和留白怎样区分；
- 表面：边框优先 / 阴影优先 / 扁平；
- 圆角：小、中、大，是否全站一致；
- 色彩：中性色比例、品牌色用途、语义色；
- 图像：实拍、插画、图标、数据图表；
- 特效：渐变、毛玻璃和动效是否有功能理由。

### 可用问题

- 这页更需要“快速扫读”还是“沉浸感”？
- 视觉重点主要靠字号和留白，还是靠颜色和卡片表面？
- 你希望界面显得严谨、亲和、精密、活泼还是编辑感？
- 参考页面中你真正想保留的是布局、密度、字体、颜色还是动效？

## 9. 微交互和动效

### 必须明确的部分

- Hover、Active、Focus、Disabled；
- 页面或内容切换是否需要 Transition；
- 加载和状态变化是否需要动画；
- 是否支持 reduced motion；
- 动画是否会延迟操作或遮挡信息。

### 原则

- 状态变化需要反馈；
- 动画服务于因果关系和空间关系；
- 高频操作应快速稳定；
- 不以持续漂浮、弹跳或大幅位移动画作为默认装饰。

## 10. 可访问性、本地化与内容弹性

### 检查项

- 键盘顺序和 Focus 可见性；
- Label、错误提示和辅助文本；
- 颜色之外的状态表达；
- 点击目标尺寸；
- 图标按钮名称；
- 对比度；
- 长文本、200% 缩放和多语言；
- 表格和图表的替代信息；
- Skip Link 或页面内导航是否必要。

### 只在会改变方案时提问

例如：

- 是否必须满足特定法规或组织级无障碍标准？
- 是否支持中英双语、从右到左语言或超长医学术语？
- 是否面向老年人、低视力用户或只能键盘操作的工作环境？

## 11. 技术和设计系统约束

优先自行检查：

- React、Vue、Next.js 等框架；
- Tailwind、CSS Modules 等样式方案；
- shadcn/ui、Ant Design、MUI 等组件库；
- 现有 Token 和主题；
- 数据接口、权限和实时更新机制；
- 浏览器和设备范围；
- 性能、包体积和 SSR 限制。

只把取舍交给用户，例如：

- 优先复用现有组件，还是允许新增一套视觉模式？
- 是否接受为了移动端体验改变桌面信息结构？
- 是否必须保持旧页面视觉兼容？

## 12. 验收标准与风险

### 验收标准应可观察

不写：

- 页面更现代；
- 体验更流畅；
- 视觉更高级。

改写为：

- 用户进入页面后无需滚动即可识别主要任务和主 CTA；
- 1280px 宽度下核心筛选、表格和详情入口同时可见；
- 375px 宽度下无横向页面滚动，表格采用已确认的移动端策略；
- 保存失败时保留输入并提供明确重试入口；
- 所有交互控件可通过键盘到达，Focus 状态清晰可见。

### 最终风险检查

- 是否存在尚未确认但会改变结构的假设；
- 是否为了视觉效果牺牲核心任务；
- 是否遗漏高频错误或权限状态；
- 是否与现有设计系统冲突；
- 是否无法在目标设备和数据规模下工作。
