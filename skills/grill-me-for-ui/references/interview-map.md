# UI Interview Map

本文件帮助 Agent 选择下一条最有价值的问题分支。它不是按顺序念完的问卷。

仅 Greenfield / World Replacement 默认使用完整双轮。Extension T1/T2 与多数 Refinement 默认先用 `core-cheatsheet.md`，只有出现新的产品或方向阻塞决策才进入本问题树。

## 使用原则

- 一次只解决一个高影响决定；
- 先检查代码、截图、品牌规范、UI Brief 和 DESIGN.md；
- 先判断表面模式和项目场景，再选问题；
- 前轮只建立边界，不提前逼用户决定全部视觉细节；
- 用户看见方向胶囊后再进入后轮；
- 增量任务沿用旧资产，不假装新项目；
- 代码后的“感觉不对”走诊断追问，不重跑需求访谈；
- 需求充分时提前结束。

### 默认问题预算

- Greenfield / World Replacement 前轮通常 3–5 题，后轮通常 3–6 题；
- T1 / T2 只问当前表面特有的 1–3 个高影响问题；
- T3 通常不进入访谈；
- 超出默认预算前，说明仍有哪些阻塞决策以及为什么不能从证据推断；
- “必须得到”表示结果必须明确，不表示每一项都要向用户提问。

## 0. 路由

### 0.1 表面模式

| 模式 | 首要问题 | 常见风险 |
|---|---|---|
| **Persuade** | 用户为什么相信并行动 | 通用 SaaS Hero、虚假社会证明 |
| **Operate** | 用户怎样快速且安全完成任务 | Card 堆砌、状态和错误恢复不足 |
| **Read** | 用户怎样理解、定位和继续阅读 | 行长、目录和层级失控 |
| **Experience** | 内容或作品如何成为主角 | 动效和界面压过作品 |

可用问题：

- 用户在这个表面成功的标志是什么：决定、完成、理解，还是沉浸？
- 如果只保留一个主要结果，它是什么？

### 0.2 项目场景

| 场景 | 进入点 | 不要做什么 |
|---|---|---|
| Greenfield | 没有可复用实现、视觉语言或设计契约 | 仅因缺少 DESIGN.md 就重跑全流程 |
| World Replacement | 已授权放弃旧视觉身份 | 在旧视觉上折中换皮 |
| Extension + T1 | 继续旧身份并新增页面 | 重做全站 Art Direction |
| Extension + T2 | 继续旧身份并新增 Section | 重新研究完整品牌 |
| Extension + T3 | 继续旧身份并做局部修改 | 生成新 Brief |
| Refinement + Depth | 继续旧身份并改善已有界面 | 用 Full structural rebuild 偷偷替换视觉身份 |

可用问题：

- 这是继续现有视觉世界，还是明确替换它？
- 本次最接近新页面、新 Section，还是现有组件 / Token 微调？
- 允许改变信息架构，还是只提升完成度？
- 如果没有书面契约，现有实现中哪些视觉规则已经稳定且应继续？

## 1. 前轮访谈：建立产品和范围边界

前轮发生在审美研究与方向胶囊之前。

### 1.1 定位与成功

必须得到：

- 一句话页面 / 产品任务；
- 主要用户；
- 用户进入和离开的路径；
- 可观察的成功结果。

问题候选：

- 陌生人只看十秒，这个页面必须让他明白什么？
- 用户进入前在做什么，离开后应该做什么？
- 三个月后你怎么判断这个页面成功了？
- 哪个结果比其他所有结果更重要？

### 1.2 必须保留与非目标

必须得到：

- 功能、内容、品牌资产和系统中必须保留的部分；
- 本次明确不做什么；
- 是否允许改变页面结构、交互或视觉世界。

问题候选：

- 当前版本中，哪一项即使不漂亮也绝不能丢？
- 本次只解决这个表面，还是允许影响前后流程？
- 哪些内容或功能已经被业务确认，不能由设计重新发明？

Operate 或高错误代价流程还需确认：

- 哪些角色可查看、执行或恢复，越权与失败时会发生什么？
- 中断后从哪里继续，哪些操作必须可撤销或回退？

### 1.3 反参考

反例通常比“喜欢什么”信息更高。

问题候选：

- 最不希望它像哪类网站或产品？为什么？
- 你看到哪些常见设计会立即觉得廉价、过度或不可信？
- 哪个竞品虽然漂亮，但不适合你的用户？

### 1.4 内容与资产

必须得到：

- 真实文案、数据、摄影、插画、图标或作品是否存在；
- 内容长度和极端情况；
- 是否允许生成 Placeholder；
- 素材质量能否支撑高表达方向。

问题候选：

- 现在有哪些真实内容和视觉资产可直接使用？
- 页面最重要的内容是产品画面、人物、作品、数据还是文字？
- 没有真实素材的区域应留占位，还是降低视觉方向对素材的依赖？

### 1.5 平台、时间和迭代方式

问题候选：

- 首要平台和视口是什么？
- 是一次性交付，还是未来会持续加页面？
- 是否已有组件库、设计系统或必须使用的平台规范？
- 时间预算允许概念探索，还是应优先使用成熟 Scaffold？

### 前轮完成标准

- [ ] 表面模式明确；
- [ ] 一句话任务和用户路径明确；
- [ ] 成功结果明确；
- [ ] 必须保留、非目标和反参考明确；
- [ ] 内容资产与实现边界明确；
- [ ] 可以生成真正不同的方向胶囊。

## 2. 审美研究与方向胶囊

需要时读取 `aesthetic-research-protocol.md`。

### 2.1 风格消歧

问题候选：

- 你说的“电影感”更接近低光摄影、叙事节奏，还是强烈转场？
- “高级”对你更重要的是克制、材质、排版，还是稀缺感？
- 参考页面中真正想借的是构图、字体、颜色、图像还是动效？

### 2.2 方向胶囊差异

每个胶囊至少在三个维度上不同。检查：

- 主导概念是否不同；
- 信息结构或交互模型是否不同；
- 表达媒介是否不同；
- 资产需求是否不同；
- 实现复杂度与风险是否不同；
- 是否只是换色。

至少一个关键差异必须来自信息结构、交互模型、内容依赖、资产要求或技术复杂度，不能全部只是视觉表面差异。

用户选择时优先问：

- 哪个方向最像这个产品应该成为的样子，而不仅是你个人最喜欢的？
- 哪个方向的风险最能接受？
- 是否要以 A 为主，只借 B 的某一个维度？

禁止把多个方向平均混合。若混合，必须明确一个主方向和一个被借用的具体维度。

## 3. 后轮访谈：看见方向后拔细节

### 3.1 页面地图与 Section 叙事

问题候选：

- 用户第一眼之后，最合理的下一步是什么？
- 首页从上到下的叙事应该是问题→证明→行动，还是作品→观点→联系？
- 哪些 Section 可以删除或合并？
- 是否需要独立详情页、Drawer、Tabs 或连续长页？

### 3.2 第一视觉锚点

问题候选：

- 第一眼应先看到标题、产品画面、人物摄影、作品还是关键数据？
- 视觉锚点主要靠尺度、位置、明暗，还是运动形成？
- 若移除 Hero H1，页面仍应由什么建立第一印象？

### 3.3 文案声音

问题候选：

- 选定方向更适合严谨、口语、编辑化、诗意，还是技术性文案？
- 主标题应直接陈述价值，还是先建立态度和情绪？
- 用户需要解释，还是已有足够领域知识？
- 哪一句现有文案最能代表品牌声音？

### 3.4 七维视觉细节

每次只选择一个维度。

#### Form

- 形态更应几何、工业、有机还是编辑化？
- 控件与内容是否共享同一形状语言？

#### Color

- 氛围色、操作色和语义色如何分工？
- 色彩应大面积塑造空间，还是保持稀缺？

#### Type

- 排版应更功能性、编辑性、表现性还是原生平台感？
- 数字、CJK、长标题和正文谁最需要特殊处理？

#### Space

- 页面更需要稳定秩序，还是一次明确破格？
- 同屏信息量和留白如何服务任务？

#### Material

- 层级主要靠边框、色块、阴影、透明、纹理还是空间？
- 该材质是否有文化或产品依据？

#### Motion

- 动效只做反馈、解释空间，还是承担叙事？
- reduced motion 下必须保留什么概念？

#### Cultural markers

- 哪些视觉信号是这个方向不可缺少的？
- 哪些标记可能被误解、过时或形成刻板印象？

### 3.5 用户担忧与反向细节

问题候选：

- 方向胶囊中哪个元素最可能让用户看不懂或觉得过度？
- 哪个效果在静态图里漂亮，但长期使用可能疲劳？
- 哪一部分最容易滑回通用模板？

### 3.6 响应式与状态

问题候选：

- 移动端第一屏必须保留哪个信息或动作？
- 主导概念在小屏如何重新表达，而不是消失？
- 表格、复杂画布、全幅摄影或强标题如何重构？
- 加载、空、错误和无权限状态是否需要保持同一视觉世界？

### 后轮完成标准

- [ ] 选定方向和 Art Direction Card 明确；
- [ ] 页面地图、第一锚点和用户路径明确；
- [ ] 文案声音明确；
- [ ] 七维视觉系统足以指导实施；
- [ ] 设计系统、图标和媒体策略明确；
- [ ] 状态与小屏不会破坏主导概念。

## 4. 增量扩展问题树

### 4.1 旧资产回放

在提问前先说明：

```text
已读取：主导概念 / Token / 组件 / 视觉锚点 / 当前页面。
本次范围：T1 / T2 / T3。
默认沿用：颜色、排版、形状、动效和系统规则。
```

用户纠正后再继续。

### 4.2 T1 新页面

只问新页面特有的：

- 它在现有产品中的任务和入口；
- 页面叙事和主要锚点；
- 是否需要新组件或新内容类型；
- 是否引入新的核心动效或媒体；
- 如何证明它仍属于现有视觉世界。

### 4.3 T2 新 Section

只问：

- 新 Section 的功能和顺序；
- 是否需要新布局母题；
- 与相邻 Section 的节奏和层级；
- 是否能复用现有组件和 Token。

### 4.4 T3 微调

通常不问完整设计问题。只确认：

- 改动目标；
- 影响范围；
- 是否改变语义或仅改变表现；
- 需要哪种定向 Review。

## 5. 代码后模糊反馈诊断

用户看完实现后说“感觉不对”，不要回到前轮。依次定位：

1. 方向是否错误；
2. 第一眼是否错误；
3. 结构、密度或节奏是否错误；
4. 排版、组件、色彩、深度或动效是否错误；
5. 内容和素材是否拖累方向；
6. 小屏或状态是否破坏体验。

可用问题：

- 更接近“方向不对”，还是“方向对但执行不够好”？
- 把颜色和动效去掉后，结构仍然不对吗？
- 最想让它更大胆、更安静、更简洁，还是更清楚？
- 第一眼看到的东西是否就是你希望的重点？

根据回答路由到 bolder / quieter / distill / typeset / layout / colorize / animate / harden / adapt。

## 6. 设计系统决策

问题候选：

- 现有系统是否是必须约束，还是可以替换？
- 平台是否有官方系统或原生交互预期？
- 策展式主题用于加速实现，还是用户真的要求相似品牌语言？
- 哪些组件必须复用，哪些可以扩展？
- 图标家族、线宽和填充风格如何统一？

不要同时混用多个主系统。

## 7. 结束条件

当前阶段满足以下条件即可停止：

- 主模式、场景和主动作明确；
- 关键方向已经选择；
- 主要替代方案被排除；
- 剩余未知不再显著改变实施；
- 用户可以确认共享理解；
- 后续问题可以在实现和有界验证中解决。

“还能想到更多问题”不是继续访谈的理由。
