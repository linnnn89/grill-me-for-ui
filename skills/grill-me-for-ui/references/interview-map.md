# UI Interview Map

本文件帮助 Agent 选择下一条最有价值的问题分支。它不是按顺序念完的问卷。

## 使用原则

- 先解决上游决策，再进入下游细节；
- 一次只选择一个尚未解决的节点；
- 只询问会改变设计、艺术指导或验收结果的事项；
- 代码、截图、品牌规范和现有页面能回答的事实先自行检查；
- 每个决定记录其对后续分支的约束；
- 高度视觉化项目应在具体布局前形成 Art Direction；
- 需求充分时提前结束，不为完整而凑问题。

## 0. 任务分类

| 类型 | 优先分支 | 主要审美风险 |
|---|---|---|
| 新产品 / 多页面应用 | 用户、范围、Art Direction、页面地图、系统 | 太早进入组件和细节 |
| 单页面新设计 | 主要任务、内容、Art Direction、构图、状态 | 漂亮但没有清晰任务 |
| 现有 UI 重设计 | 保留项、痛点、现状审计、迁移边界 | 只换皮或破坏已知习惯 |
| Dashboard / 后台 | 数据任务、密度、扫读、表格、详情 | 卡片墙、层级平均化 |
| Landing / 官网 | 受众、承诺、证据、品牌记忆、CTA | 通用 SaaS 模板 |
| Portfolio / 创意展示 | 作品、个人态度、节奏、图像、动效 | 设计压过作品 |
| Editorial / 内容页 | 阅读、排版、图像、章节节奏 | 用风格标签代替内容设计 |
| 表单 / 多步流程 | 输入、验证、保存、恢复、完成 | 只设计正常提交 |
| 消费型移动端 | 高频任务、触感、导航、内容密度 | 概念稿效果影响长期使用 |
| 社区 / 娱乐产品 | 参与、身份、活力、内容生成 | 视觉噪声和系统失控 |
| 独立组件 | 用途、变体、状态、组合和视觉角色 | 不可复用或脱离系统 |
| 设计系统 | 原则、Token、组件关系、治理 | 规则很多但没有视觉概念 |

## 1. 问题、用户与主要结果

### 必须得到

- 主要用户是谁；
- 用户进入时想完成什么；
- 最重要的一个结果或动作；
- 使用频率和熟练程度；
- 当前方案为什么失败或新方案为什么需要存在。

### 高价值问题

- 用户完成这页后，最重要的变化是什么？
- 若只能保留一个主要动作，应该是哪一个？
- 用户是第一次使用、偶尔使用，还是每天重复操作？
- 当前主要问题是找不到、看不懂、操作慢、不信任，还是缺少品牌吸引力？
- 五秒后用户应该记住产品能力、品牌态度、内容还是一个操作结果？

### 依赖

没有明确主要任务前，不决定 CTA、页面重心和视觉表达强度。

## 2. 范围、非目标与成功标准

### 必须得到

- 本次包含哪些页面、流程或组件；
- 哪些功能和内容必须保留；
- 是否允许改变信息架构、交互、视觉系统或技术基础；
- 时间和资源边界；
- 怎样判断重设计有效。

### 高价值问题

- 本次只改当前页面，还是允许调整前后流程？
- 哪些已有行为、内容或品牌资产不能改变？
- 成功更看重完成率、速度、理解度、转化、品牌记忆还是整体质感？
- 若时间不足，什么可以延后？
- 这是保守升级、明显重塑，还是从零建立新语言？

## 3. 内容、数据与资产

视觉方向必须建立在真实内容上。

### 必须得到

- 必须展示的内容与数据；
- 第一眼、完成任务和按需查看的信息；
- 数据量、内容长度和更新频率；
- 编辑、筛选、比较、分享和导出需求；
- 已有文案、摄影、插画、作品、图标或品牌资产；
- 哪些内容仍是 Placeholder。

### 高价值问题

- 第一眼必须看到什么？
- 哪些内容可以折叠、放入 Drawer 或延后？
- 页面面对的是几条、几十条还是上万条数据？
- 用户主要扫描、比较、搜索、阅读还是操作？
- 最长标题、名称、翻译或数字可能多长？
- 当前是否有足以支撑强图像方向的高质量素材？
- 哪些指标、客户、评价或品牌声明明确不能生成？

### 典型判断

- 少量同类对象：List、Card 或自由编排；
- 多字段比较：Table；
- 单个对象：分区详情；
- 指标概览：Statistic，但不能代替完整信息；
- 高质量图像不足：不要选择以全幅影像为核心的方向；
- 文案未成熟：避免依赖超大标题和复杂叙事节奏。

## 4. Art Direction Card

在具体布局和组件前形成艺术指导。

### 必须得到

- 三个具体气质词；
- 一个明确反形容词；
- 一句视觉命题；
- 主要视觉张力；
- 主导表达媒介；
- 最容易出现的设计漂移。

### 高价值问题

- 这页首先应该让人感到可信、渴望、精密、亲和、活力还是文化感？
- 主要张力更适合“秩序 × 破格”“精密 × 亲和”“克制 × 戏剧性”，还是其他组合？
- 视觉识别应主要来自构图、排版、图像、色彩、材质还是动效？
- 哪个词最不应该形容最终页面？
- 这个品牌需要保持距离感，还是主动建立亲近感？
- 设计应该显得长期稳定，还是带有明显的当下文化表达？

### 三项旋钮

由 Agent 根据证据先推断：

- `EXPRESSION`；
- `MOTION`；
- `DENSITY`。

只有真实分歧时才让用户调数字。

### 方向分叉

高度视觉化项目若存在明显歧义，可提供 2–3 条实质不同路线。路线必须在至少三项上不同：构图、排版、图像、色彩、材质、动效或品牌态度。

不要提供仅换字体和颜色的伪方案。

## 5. 主导概念与支持母题

### 必须得到

- 一个主导概念；
- 最多两个支持母题；
- 其他元素如何退后；
- 主导概念如何在不同页面或视口延续。

### 高价值问题

- 如果只能保留一个视觉概念，应该是什么？
- 这个概念最适合通过构图、排版、图像、材质还是交互表达？
- 哪两个重复元素能强化它，而不产生新主题？
- 去掉 Logo 后，什么仍能让用户认出这是同一产品？
- 主导概念在移动端如何保留？

### 失败信号

- 同时使用多个风格标签；
- 每个 Section 都有自己的“亮点”；
- 母题只能描述为蓝色、圆角、渐变；
- 概念与真实内容无关。

## 6. 页面地图、导航与核心流程

### 必须得到

- 用户从哪里进入；
- 完成任务经过哪些页面或状态；
- 主导航与局部导航如何分工；
- 成功、失败、中断和返回路径；
- 哪些页面共享同一艺术指导，哪些需要有意变化。

### 高价值问题

- 用户通常从首页、搜索、通知、分享还是外部链接进入？
- 任务应在一页完成，还是拆成步骤？
- 中断后下次从哪里继续？
- 返回上一级时，筛选、滚动和未保存内容是否保留？
- 深层页面是否需要 Breadcrumb？
- 多页面之间更需要稳定重复，还是允许少数关键页面形成高潮？

### 导航判断

- 少量顶级区域：Top Nav；
- 多模块高频切换：Sidebar；
- 长内容：Anchor / Sticky TOC；
- 明确流程：Steps；
- 大量结果：Pagination、Infinite Load 或虚拟滚动，由任务决定。

## 7. 构图语法

先决定宏观秩序，再选择组件。

### 必须得到

- 第一视觉锚点；
- 视线进入、流动和结束方式；
- 大小、密疏、长短和静动节奏；
- 主要视觉对比；
- 留白的角色；
- 边缘、裁切和对齐逻辑。

### 高价值问题

- 第一眼应落在标题、产品画面、人物、数据还是操作？
- 页面是稳定网格主导，还是允许一次明显破格？
- 重点主要靠尺寸、位置、颜色、图像还是空白建立？
- 页面需要连续画布、分明章节，还是高度模块化结构？
- 宽屏应展示更多并列信息，还是保持强留白和聚焦？
- 哪些内容应该视觉上同时出现？

### 构图检查

- 是否有唯一第一锚点；
- 是否有清楚的第二层路径；
- 是否连续重复同一 Section 结构；
- 是否所有模块权重接近；
- 留白是否形成停顿和张力；
- 出血与对齐是否坚定。

## 8. 布局与响应式结构

### 必须得到

- 主布局模式；
- 内容最大宽度和密度；
- 桌面、平板和手机的优先级；
- 小屏下哪些重排、折叠、替换或延后；
- 主导概念如何跨视口保留。

### 高价值问题

- 这页更像操作工作台、阅读体验、品牌叙事还是浏览目录？
- 用户需要同时看到导航、列表和详情吗？
- 手机端最核心的一项任务是什么？
- 桌面表格在手机上应横向滚动、减少列、转摘要还是进入详情？
- 全幅图像、非对称布局或超大排版在手机端如何重新编排？
- 是否存在不适合简单单列的内容关系？

响应式不是桌面机械缩小或全部单列，而是重新确认每个视口的锚点、任务和节奏。

## 9. 组件与交互选择

### 判断顺序

1. 用户动作；
2. 内容和数据结构；
3. 状态与恢复；
4. Art Direction 和视觉角色；
5. 最后才是组件名称和外观。

### 高价值问题

- 设置是立即生效，还是统一保存？
- 选项互斥、可多选，还是从大量候选中搜索？
- 查看详情时需要保留背景上下文吗？
- 删除或提交是否可撤销？
- 次级信息应悬停解释、点击展开还是永久可见？
- Card 是否真的表达分组或层级，还是只因为模板常用？

### 典型映射

- 二元立即生效：Switch；
- 少量互斥：Radio / Segmented；
- 多选：Checkbox；
- 大量候选：Select / Autocomplete；
- 保留上下文详情：Drawer；
- 阻塞性短任务：Modal；
- 邻近确认：Popconfirm；
- 非阻塞短反馈：Toast；
- 持续重要信息：Alert。

## 10. 状态、错误与恢复

对每个关键动作检查：

- 初始；
- 加载和局部加载；
- 空和单条数据；
- 部分失败；
- 输入验证；
- 请求失败、重试和超时；
- 成功；
- 无权限、只读和禁用；
- 破坏性确认、撤销和恢复；
- 重复点击和并发；
- 未保存内容。

### 高价值问题

- 用户等待超过一秒时，最需要知道什么？
- 没有数据时，下一步是什么？
- 保存失败后必须保留哪些内容？
- 成功后留在原地、进入详情、显示结果还是返回列表？
- 删除不可逆、软删除还是支持撤销？

状态视觉必须属于同一艺术指导，而不是使用完全不同的插画和颜色系统。

## 11. 视觉系统六层

使用 `taste-calibration.md` 逐层落地。

### Typography

- 排版声音；
- 标题与正文比例；
- 字号、字重、字宽、行高和断行；
- 数字、标签和元信息；
- CJK、拉丁、多语言和长文本。

### Color

- Atmosphere；
- Action；
- Semantic；
- 明暗关系与对比；
- 深色模式和高对比模式。

### Shape

- 圆角、直角、切角和圆形角色；
- 控件、容器、图像和品牌轮廓关系；
- 图标线宽与视觉重量。

### Material & Depth

- 平面、边框、色块、阴影、透明或纹理；
- 浮层和容器层级；
- Card 必要性；
- 透明度降级。

### Imagery / Illustration / Iconography / Data Visualization

- 素材主题、镜头、色调和裁切；
- 插画几何、笔触和透视；
- 图标家族；
- 图表类型、颜色编码和注释；
- 素材质量是否匹配视觉野心。

### Motion

- 即时反馈；
- 空间解释；
- 叙事编排；
- 环境运动；
- reduced motion 和性能。

## 12. 参考设计三角拆解

理想情况下使用 2–3 个参考：

1. 构图参考；
2. 排版或色彩参考；
3. 图像、材质或动效参考。

每个参考记录：

- 借鉴什么；
- 不借鉴什么；
- 为什么适合当前项目；
- 如何转化为当前规则。

不要复制参考品牌的识别性元素，也不要把“像 Apple / Linear / Notion”当作完整方向。

## 13. 可访问性、本地化与内容弹性

检查：

- 键盘顺序和 Focus；
- Label、错误和辅助文本；
- 非颜色状态表达；
- 点击目标；
- 对比度；
- 长文本、200% 缩放和多语言；
- 图表与图像替代信息；
- 动效降级。

只询问会改变方案的边界，例如特定法规、老年用户、RTL、超长术语或只能键盘操作的环境。

## 14. 技术与设计系统约束

优先自行检查：

- 框架与样式方案；
- 组件库和现有 Token；
- 已有品牌字体和素材许可；
- 数据、权限和实时更新；
- 浏览器、设备、性能、SSR 和包体积；
- 动画与图像处理能力；
- 必须复用的组件和允许新增的基础设施。

技术系统应服务 Art Direction，不要因为已有组件库就默认保留其开箱即用视觉状态。

## 15. 验收与视觉 Critique

### 功能验收

- 主要任务可识别；
- 成功与失败路径完整；
- 状态和恢复可验证；
- 键盘和移动端可用；
- 内容增长不破版。

### 视觉验收

- 五秒内能感知 Art Direction；
- 第一视觉锚点正确；
- 主导概念和支持母题清晰；
- 构图、节奏和视觉系统一致；
- 隐去 Logo 后仍有品牌指纹；
- 不依赖假内容和模板区块；
- 关键视口保留同一视觉身份。

### 实施后

使用 `visual-critique.md` 执行：

- 五秒印象；
- Squint Test；
- 灰度层级；
- 构图与视线流；
- 品牌指纹；
- 排版；
- 色彩、形状和材质；
- 图像、图标和图表；
- 动效；
- 响应式；
- 真实与极端内容。

问题按 P0 方向、P1 结构、P2 完成度和 P3 偏好分级。

## 页面类型专用分支

### Landing / 官网

- 一句话承诺；
- 主要受众和转化；
- 证据与社会证明真实性；
- Hero 的视觉锚点；
- 页面叙事高潮；
- 品牌记忆来自哪里；
- CTA 意图是否唯一清晰。

### Dashboard / 数据工具

- 用户要监测、比较、诊断还是操作；
- 最重要数据和异常；
- 信息密度；
- 筛选、表格、图表和详情关系；
- 数据新鲜度和可信度；
- 扫读秩序是否可成为主导概念。

### Portfolio / 创意展示

- 作品还是个人品牌谁是主角；
- 项目排序和叙事；
- 图像质量与裁切；
- 个人态度如何表达；
- 动效是否强化作品；
- 招聘者或客户五秒内看到什么。

### Editorial / 内容产品

- 阅读任务；
- 内容长度和节奏；
- 标题、正文、注释和媒体层级；
- 目录、锚点和搜索；
- 图像与文字关系；
- 排版本身是否承担主导概念。

### 表单 / 多步流程

- 字段和步骤；
- 验证时机；
- 保存与恢复；
- 错误代价；
- 完成反馈；
- 视觉表达是否支持安心和进度感。

### 重设计

- 必须保留什么；
- 当前最强和最弱的视觉资产；
- 功能问题还是品牌问题；
- 保守升级还是明显重塑；
- 迁移风险；
- 前后对照标准；
- 哪些旧习惯是资产，哪些只是历史包袱。
