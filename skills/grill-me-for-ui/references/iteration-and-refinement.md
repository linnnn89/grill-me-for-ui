# Iteration and Refinement Playbook

本文件用于已有 UI、视觉稿或代码之后的迭代。它解决三个常见问题：模型把局部修改扩大成重设计；用户只能说“感觉不对”；Agent 无限截图和微调，消耗大量时间与上下文。

## 一、先锁定变更语义

### Refinement · 延续并提升

保留：

- 现有产品和品牌身份；
- 信息架构和行为；
- 已确认文案与真实内容；
- 任务范围外的区域；
- 成熟 Token 和组件规则。

只修复本次目标相关的问题。

### Redesign · 替换视觉世界

保留产品真相、功能、内容和平台约束，但旧视觉语言只是证据或反参考。必须重新定义 Art Direction、系统策略和迁移边界。

不要把已经被否定的旧方向“精修后保留一半”。

## 二、选择重写深度

| 深度 | 可以改变 | 不应改变 | 适用情况 |
|---|---|---|---|
| **Light polish** | 间距、排版、状态、颜色角色、细节一致性 | 页面结构、流程、内容层级 | 结构成立但完成度不足 |
| **Medium restructure** | 分组、布局、组件层级、Section 顺序 | 核心任务和产品逻辑 | 层级或构图有结构性问题 |
| **Full rebuild** | 构图、组件系统、视觉世界和页面结构 | 真实功能、数据和约束 | 当前方向无法通过局部修复成立 |

编辑前先声明重写深度、核心失败和预期效果。

## 三、把模糊反馈语言化

用户说“怪、土、AI 味、没高级感、太平、太花”时，不立即修改。先定位它属于哪一层：

1. 方向：Art Direction 与产品不匹配；
2. 层级：第一眼、主次和视线流错误；
3. 密度：过空、过挤或节奏平均；
4. 排版：声音、比例、断行或可读性；
5. 组件：尺寸、几何、状态和一致性；
6. 色彩：中性色不稳、强调滥用或语义混乱；
7. 深度：表面、边框、阴影、透明和层级；
8. 动效：速度、因果、注意力或性能；
9. 内容：假文案、低质量素材或信息结构；
10. 平台：移动端、系统原生感或可访问性。

给出最可能的 2–3 个诊断，并问一个能够区分它们的问题。

## 四、定向精修动作

### bolder · 更大胆

用于设计安全、平均、没有观点时。优先：

- 放大主导概念，而不是添加多个效果；
- 增强一个主要视觉锚点；
- 拉开排版、尺寸或明暗对比；
- 删除削弱张力的次级容器；
- 让品牌指纹在多个区域稳定出现。

不要把“更大胆”理解为更多渐变、动画和更大字号。

### quieter · 更安静

用于视觉层级互相竞争、默认状态花费太多强调时。优先：

- 降低次级模块的对比和表面重量；
- 合并重复色彩、边框、Badge 和 Chip；
- 删除无意义持续动画；
- 减少同层级的字体和形状变化；
- 把强调留给操作、状态和真正重点。

### distill · 提纯

用于功能和装饰堆叠。顺序：

1. 删除不服务核心任务的内容；
2. 合并重复 Section 和组件；
3. 用空间分组替代不必要 Card；
4. 减少 CTA 意图和文案变体；
5. 保留最能表达主导概念的少量规则。

### typeset · 排版

检查：

- 标题、正文、标签、数据和元信息是否各有角色；
- 字号比例和字重是否形成清晰层级；
- 断行是否有意；
- 行长、行高、段落和 CJK 回退；
- 数字、单位、小数位和表格对齐；
- 小字号和浅色文字是否以“精致”为名损害可读性。

### layout · 构图

从宏观到微观：

- 第一视觉锚点；
- 视线流和下一步动作；
- 网格、对齐和页面边缘；
- 密疏、大小、长短和停顿；
- Section 结构是否机械重复；
- 小屏是否重新编排重点。

### colorize · 色彩

先稳定中性色，再引入色彩。区分：

- Atmosphere：环境和品牌气氛；
- Action：主要操作和交互；
- Semantic：成功、警告、错误和信息。

同一颜色不应同时承担互相冲突的角色。强调色应稀缺，但不机械限制为一个。

### animate · 动效

只为以下目的添加：

- 状态反馈；
- 进入、离开和展开；
- 空间关系；
- 进度和因果；
- 低频叙事。

必须定义触发、时长、方向、退出、打断和 reduced-motion 行为。

### delight · 愉悦

只添加少量与品牌或任务相关的记忆点。它不能遮挡核心内容，也不能成为错误恢复或高频操作的负担。

### harden · 生产加固

覆盖：

- 加载、空、失败、成功、无权限和禁用；
- 重复提交、并发、离线和恢复；
- 长文本、真实数据极值和 i18n；
- 键盘、Focus、屏幕阅读和对比度；
- 性能、媒体失败和降级。

### adapt · 平台与设备适配

不是压缩桌面端，而是重新决定：

- 第一屏保留什么；
- 哪些同时可见，哪些进入下一层；
- 导航和主要动作如何变化；
- Hover 如何转为触控；
- 表格、图表和复杂编辑器如何重构；
- iOS、Android、Web 或 TV 的原生预期。

## 五、媒体与动效技术阶梯

从最低复杂度开始，仅在概念需要时升级：

1. **Static CSS / SVG**：排版、构图、渐变、纹理和静态插画；
2. **CSS transitions / keyframes**：简单 Hover、进入和状态反馈；
3. **Motion library**：复杂状态、布局连续性、滚动和手势；
4. **Lottie / Rive**：可控矢量动画、状态机和品牌角色；
5. **Video / image sequence**：电影式叙事或真实产品画面；
6. **Spline / Web-based 3D**：轻量交互场景和产品对象；
7. **Canvas / Three.js / WebGL / shaders**：只有实时视觉计算本身是核心体验时使用。

每次升级都必须回答：

- 更低层技术为什么不足；
- 对首屏性能和移动设备的影响；
- reduced motion 和低性能回退；
- 媒体加载失败时的静态替代；
- 是否有足够资产和实现能力。

不要为了“高级”自动选择 3D、粒子、Bloom 或 Shader。

## 六、机械检测与专业判断分离

### Machine-detectable · 可机械检查

适合规则、脚本或浏览器自动化：

- 对比度；
- 缺少 Label、alt、Focus；
- 横向溢出；
- 点击目标尺寸；
- 断链和资源失败；
- 重复 ID、无效 HTML；
- 视口、截图尺寸和空白 Canvas；
- 动画是否尊重 reduced motion；
- 文本截断和未处理 Overflow；
- 性能预算。

### Judgment-only · 需要设计判断

- Art Direction 是否适合产品；
- 第一视觉锚点是否正确；
- 构图和节奏是否成立；
- 品牌指纹是否独特；
- 视觉张力是否过强或不足；
- 参考转译是否变成模仿；
- 页面是否“安全但平庸”；
- 动效是否具有叙事和因果价值。

自动检测不能替代 Critique，Critique 也不应把机械错误包装成个人品味。

## 七、有界验证协议

禁止无限循环“截图—微调—再截图”。默认最多两轮。

### Pass 1 · 批量发现

一次准备并检查：

- 主要桌面和移动视口；
- 首屏和长截图；
- 关键状态；
- 真实和极端内容；
- 机械检测结果；
- Art Direction Card 与 DESIGN.md。

把发现合并成一个修复批次，按 P0–P3 排序。

### Fix batch · 一次性修复

- P0 方向问题优先；
- P1 结构性问题其次；
- P2 完成度问题集中处理；
- P3 偏好差异默认不改，除非用户确认。

不要在批次中不断新增范围。

### Pass 2 · 确认

只确认：

- P0/P1 是否关闭；
- 修复是否引入回归；
- 主要桌面、移动和状态是否通过；
- 是否满足交付标准。

通过后停止。仍有阻塞问题时如实报告，不进入无上限精修。

## 八、证据输出

最终报告应包含：

- 本轮主动作和重写深度；
- 保留项与改变项；
- P0–P3 问题；
- 已验证的视口和状态；
- 自动检查与人工判断的边界；
- 前后关键差异；
- 尚未解决但不阻塞的事项。

没有截图、交互或等价证据时，不声称视觉结果已经通过验证。
