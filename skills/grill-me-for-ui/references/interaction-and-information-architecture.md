# Interaction and Information Architecture

复杂 Operate、多页面产品或结构性重写仍存在对象、动作、导航、权限、状态或任务连续性等高影响不确定性时读取本文件。目标是在锁定视觉方向前解决产品结构。

T3 和纯视觉精修继续使用轻量路径。当交互结构已经足以指导布局与组件选择时，本阶段结束。

## 1. 建立任务模型

提问前先从项目证据恢复：

- 用户的主要目标与可观察完成结果；
- 进入情境、离开去向、任务频率和错误代价；
- 用户实际查看或改变的对象；
- 每类对象允许执行的动作；
- 角色、权限、所有权和协作边界；
- 必须同时可见的数据或内容关系。

只询问会改变当前模型的下一项决定。视觉偏好不能替代缺失的产品结构。

## 2. 建模对象、动作与关系

使用真实产品语言，不先用 Card、Tab 或 Drawer 代替产品概念。

| 元素 | 需要明确的内容 |
|---|---|
| Objects | 用户识别、比较、创建、编辑、组织或分享的对象 |
| Attributes | 标识对象或影响决定的属性 |
| Actions | 可执行动作、作用范围及其后果 |
| Relationships | 父子、成员、顺序、所有权、依赖或比较关系 |
| Roles | 谁可以查看、改变、批准、恢复或管理 |

页面、卡片、标签页或抽屉属于实现选择。先定义产品关系，再选择界面形式。

## 3. 选择信息架构

为每个主要表面选择一个主要组织原则：

- **Object-based：** 围绕项目、患者、文件、订单等稳定对象导航；
- **Task-based：** 从少量明确任务进入；
- **Sequence-based：** 流程具有顺序、阶段和完成状态；
- **Role-based：** 不同职责需要不同默认视图；
- **Time-based：** 时间、版本、日程或最近活动是主要检索模型。

记录必要的次级原则及其适用范围，不把多个全局导航模型放在同一层级竞争。

检查：

- 用户会去哪里寻找对象或动作；
- 跨页面需要持续保留哪些上下文；
- 哪些内容属于全局导航、局部导航、筛选、搜索或对象动作；
- URL、返回、深链和再次进入是否保持用户的心理位置；
- 哪些信息必须同时可见，才能比较或安全操作。

## 4. 描述主流程与关键分支

先描述最短成功路径，再补充会改变设计的分支：

```text
进入情境
→ 识别或选择对象
→ 查看必要信息
→ 作出决定或执行动作
→ 得到反馈
→ 继续、恢复或离开
```

对每个关键决定点记录：

- 用户此时知道什么；
- 可用动作与最可能的默认动作；
- 操作是否可撤销、可中断或具有破坏性；
- 什么反馈能让结果可理解；
- 失败或离开时必须保留什么。

只纳入会改变导航、层级、状态、权限或恢复的流程，不扩写全部边缘情况。

## 5. 按维度定义状态转换

使用当前产品需要的维度，不把不同性质的状态压成一个平面清单：

- **Data：** initial、loading、ready、empty、partial、stale、failed；
- **Action：** idle、pending、succeeded、failed、rolled back；
- **Permission：** editable、read-only、denied；
- **Connection：** online、offline、reconnecting；
- **Document / Form：** clean、dirty、saving、saved、conflict。

对关键转换记录：

| 触发事件 | 用户可见状态 | 可执行动作 | 退出或恢复 | 保留上下文 |
|---|---|---|---|---|
|  |  |  |  |  |

根据转换含义选择反馈和恢复方式。Skeleton、Spinner、Optimistic update、Undo、确认和阻塞式对话框都是候选手段，不是默认答案。

## 6. 跨设备转换任务

响应式设计保留任务含义，不要求所有信息始终同时可见。

记录：

- 第一屏必须保留的对象、决定或动作；
- 哪些关系必须并排比较；
- 哪些内容可以进入下一层而不丢上下文；
- Hover、键盘快捷键、拖放和密集表格如何转为触控或小屏行为；
- 是否应优先采用平台原生导航或输入约定。

设备无法安全支持完整任务时，明确较窄的支持范围，不机械压缩桌面界面。

## 7. 交互模式研究，按需

领域惯例、平台约定或同类产品的任务模型可能改变结构时，进行有界研究。优先查看官方平台规范、同类产品的真实流程和当前项目证据，区分：

- 观察到的交互模式；
- 它支持的用户目标；
- 适合借用的行为或信息关系；
- 不适合当前权限、内容或风险的部分；
- 仍需由用户决定的产品取舍。

借用行为语义，不复制品牌外观。新增来源不再改变对象、流程、导航或恢复选择时停止研究。

## 9. 停止条件
