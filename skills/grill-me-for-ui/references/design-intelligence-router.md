# Design Intelligence Router

本文件负责判断当前 UI 任务真正需要哪一种设计能力，并选择最小执行路径。它吸收检索式设计知识库、命令式精修工具和分阶段设计流程的优点，但不要求每次加载全部参考资料。

## 一、先判断表面模式，而不是产品类别

同一个产品可以拥有不同表面。开发者工具的官网仍是说服界面，时尚品牌的帮助中心仍是阅读界面。

| 模式 | 用户成功的定义 | 典型表面 | 设计优先级 |
|---|---|---|---|
| **Persuade · 说服** | 用户理解价值并采取行动 | Landing、定价、活动页、品牌官网 | 注意力、叙事、信任、转化 |
| **Operate · 操作** | 用户高效完成任务 | App、Dashboard、后台、编辑器、设置 | 扫读、反馈、一致、错误恢复 |
| **Read · 阅读** | 用户理解并保留信息 | 文档、文章、指南、新闻、更新日志 | 结构、行长、节奏、导航、搜索 |
| **Experience · 体验** | 内容或作品本身成为体验 | Portfolio、画廊、互动展示、文化品牌 | 作品优先、沉浸、节奏、记忆 |

模式以当前表面为准，不以公司所属行业为准。一个页面只能有一个主模式；可以记录一个次模式，但不能用它为互相冲突的设计目标辩护。

## 二、判断项目场景

### A. Greenfield · 全新方向

不存在成熟 UI Brief / DESIGN.md，或现有材料不足以约束新设计。

最小路径：

```text
前轮访谈
→ 审美研究与方向胶囊
→ 后轮访谈
→ 锁定 Art Direction 与设计契约
→ 实施或交付
→ 有界验证
```

### B. World Replacement · 视觉世界替换

产品真相、功能和内容保留，但旧视觉语言不再继续。

必须明确：

- 哪些功能、文案、数据和行为必须保留；
- 旧系统是证据还是约束；
- 哪些 Token、组件和资产被废弃；
- 迁移风险和前后对照标准。

不要把旧系统和新方向折中成“稍微换皮”。

### C. Extension · 增量扩展

已有定稿设计契约，需要新增页面、Section 或组件。

先读取旧资产，再按范围分级：

| Tier | 范围 | 默认路径 |
|---|---|---|
| **T1 新页面** | 新路由或独立页面组 | 轻量后轮 → 局部视觉锚点 → 实施 → Review |
| **T2 新 Section** | 已有页面新增一个主要区块 | 最小后轮 → 可选方向草图 → 实施 → Review |
| **T3 微调** | Token、单组件、状态或动效参数 | 直接实施 → 定向 Review → 回写契约 |

若一个请求跨 Tier，拆成多个连续范围，不要一次混做。

### D. Refinement · 现有界面精修

结构基本可用，用户希望提升完成度。先确定重写深度：

- **Light polish**：不改变信息架构，只调整层级、间距、排版、状态和视觉一致性；
- **Medium restructure**：允许重新分组、改变布局和组件层级；
- **Full rebuild**：当前构图或视觉世界无法修复，需要重建，但保留产品真相。

## 三、选择工作动词

用户不需要记住命令名。Agent 根据意图选择一个主动作；两个动作同样合适时只问一次。

| 动作 | 解决什么问题 | 典型输出 |
|---|---|---|
| **shape** | 在代码前澄清产品、流程与视觉方向 | UI Brief、Art Direction Card |
| **research** | 风格词含糊、需要参考和文化语义 | 方向研究、候选审美、风险 |
| **direct** | 需要明确艺术指导而非更多选项 | 方向胶囊、选定方向 |
| **document** | 从现有实现提炼设计系统 | DESIGN.md、Token、组件规则 |
| **critique** | 判断“为什么不对” | P0–P3 评审报告 |
| **audit** | 检查可访问性、响应式、性能与机械错误 | 可验证问题清单 |
| **polish** | 交付前整体完成度提升 | 精修修改与前后差异 |
| **bolder** | 设计过于安全、缺乏观点 | 放大主导概念和视觉张力 |
| **quieter** | 设计过度刺激、层级失控 | 降低噪声并恢复主次 |
| **distill** | 结构和装饰过多 | 删除、合并与本质化方案 |
| **typeset** | 排版声音、层级或断行薄弱 | 类型比例、字重、行长和数据排版 |
| **layout** | 构图、间距、视线流和节奏薄弱 | 网格、对齐、密疏与响应式调整 |
| **colorize** | 色彩过于单调或角色混乱 | Atmosphere / Action / Semantic 色彩策略 |
| **animate** | 需要解释空间关系或状态因果 | 动效语法、时长、降级方案 |
| **delight** | 需要少量品牌记忆与情感反馈 | 受控的愉悦点，不改变核心流程 |
| **harden** | 需要达到生产环境边界 | 错误、空状态、长文本、i18n、权限 |
| **adapt** | 需要跨设备或平台迁移 | 重构后的设备与平台策略 |
| **verify** | 需要证明结果已经完成 | 截图、状态、机械检查与 Critique |

一次迭代只设一个主动作，最多附带一个支持动作。例如：`layout + quieter`，而不是同时运行五种精修意图。

## 四、双轮访谈路由

### 前轮：建立边界

发生在审美研究和方向生成前。优先解决：

- 一句话产品 / 页面任务；
- 主要用户与进入、离开路径；
- 当前表面模式；
- 必须保留与明确非目标；
- 反参考：最不希望像什么；
- 真实内容和资产质量；
- 时间、平台和迭代方式。

前轮不深入询问颜色、字体和具体组件。

### 中间：生成方向胶囊

前轮后，由 Agent 基于证据生成 2–3 个真正有差异的方向胶囊，而不是四个只换颜色的页面方案。

每个方向胶囊包含：

```text
名称：
一句视觉命题：
三个气质词 + 一个反形容词：
表面模式：
主导概念：
主要张力：
七维摘要：Form / Color / Type / Space / Material / Motion / Cultural markers
需要的内容资产：
最大收益：
最大风险：
与其他方向的关键差异：
```

方向胶囊可以配参考图、文字 Moodboard 或低成本草图，但不要先写完整生产代码。

### 后轮：看见方向后拔细节

发生在方向胶囊或 Moodboard 被选定后。用户此时更容易表达隐性判断。

优先解决：

- 页面地图和 Section 叙事；
- 第一视觉锚点与下一步动作；
- 文案语气与内容长度；
- 选定方向中哪些元素最重要、哪些令人担忧；
- 构图、排版、图像与动效的边界；
- 小屏和状态如何保留主导概念；
- 设计系统与实现策略。

## 五、检索式知识加载

不要在每次任务中加载完整风格目录。根据当前问题只检索一个或数个域：

1. 产品 / 表面模式；
2. 审美方向或文化语义；
3. 色彩与排版；
4. 页面模式和信息结构；
5. 图表或数据表达；
6. 设计系统与组件；
7. 动效与媒体技术；
8. 反模式与可访问性。

### 排序原则

候选方向按以下顺序评估：

1. 是否服务真实任务和受众；
2. 是否适合当前表面模式；
3. 是否与品牌和内容资产匹配；
4. 是否在平台、性能和无障碍边界内可实现；
5. 是否能形成辨识度；
6. 是否依赖未经提供的高质量素材；
7. 是否只是当前流行模板。

数据库或目录提供候选，不替代专业判断。行业匹配也不是审美结论。

## 六、设计系统策略

根据项目选择一种基础：

### 1. Existing system · 复用现有系统

适合成熟产品。先识别 Token、组件和视觉真相，明确允许偏离的范围。

### 2. Official system · 官方系统

适合平台或组织有明确规范的项目。使用官方包和语义 Token，不手写仿制版本。

### 3. Curated scaffold · 策展式脚手架

可以用成熟主题或品牌型系统作为实现起点，但必须：

- 说明借用的是哪些维度；
- 替换品牌专属识别元素；
- 不将“像 Linear / Stripe / Apple”当成最终 Art Direction；
- 检查组件代码而不只复制颜色变量。

### 4. Custom system · 自定义系统

当品牌或交互要求无法由现成系统表达时使用。至少定义语义颜色、排版、间距、形状、深度、图像、动效和核心状态。

一个表面只使用一个主系统。图标也选择一个主家族，并记录线宽、填充和尺寸规则。

## 七、上下文与 Token 控制

- 主 Skill 只负责路由；
- 每轮只加载当前动作对应的一份核心参考；
- 大型风格、配色和组件目录按查询加载，不常驻上下文；
- 增量任务先读旧 DESIGN.md 的相关章节，不重新载入全部研究资料；
- 只有结构性方向变化才回到完整研究和后轮访谈；
- 不为简单 T3 调整生成完整新 Brief。

## 八、停止条件

当以下条件成立时停止访谈或研究：

- 当前主动作已经明确；
- 选定方向足以排除主要替代方案；
- 剩余未知不会显著改变实施；
- 用户确认的范围、资产和设计系统策略明确；
- 后续可以通过实现和验证继续收敛。

不要以“还有更多问题可问”为继续访谈的理由。
