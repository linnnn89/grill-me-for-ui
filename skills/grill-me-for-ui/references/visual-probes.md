# Visual Probes

重要设计选择仍难以通过文字判断时使用 Visual Probe。Probe 是解决当前不确定性的最小可见证据，不是实施承诺，也不是伪装成最终稿的完整设计。

## 1. 明确未决决定

创建任何视觉产物前先完成：

```text
用户暂时无法在[替代方案]之间选择，
因为[需要被看见的差异]仍然抽象。
```

若未决问题属于产品范围、权限、数据含义或业务行为，返回相应决定阶段。视觉产物不能替用户解决这些问题。

## 2. 选择最低有效保真度

| 未决决定 | Probe | 必须呈现 |
|---|---|---|
| 审美语义或参考转译 | Reference board / Moodboard | 构图、排版、色彩、图像、材质及明确不借用的特征 |
| 信息层级或页面结构 | 灰阶 Wireframe | 锚点、分组、顺序、密度、导航和主要动作 |
| 交互模型或状态变化 | 小型状态 Prototype | 触发、前后状态、反馈、中断和恢复 |
| Art Direction 在真实产品中的表达 | 代表性 Key screen | 真实内容、主导概念、视觉系统和一个关键状态 |
| 响应式转换 | 成对桌面 / 移动构图 | 哪些保留、移动、折叠或进入下一层 |

保真度只服务当前决定。优先一个关键屏而非完整产品，优先一组状态前后对照而非完整可点击应用。

## 3. 保持比较公平

需要多个 Probe 时：

- 保持产品真相、核心内容、平台和硬约束相同；
- 只改变正在比较的结构、交互或视觉决定；
- 优先使用真实内容和资产；
- 每个方向至少在两个相关维度上形成可见差异；
- 标明假设与缺失资产；
- 只有实现成本会改变选择时才记录成本。

两个 Probe 已能覆盖主要替代方案时不增加第三个。第三个方向必须真正不同。

## 4. 使用当前可用的视觉能力

选择当前环境中能够生成并展示所需保真度的工具。展示前先检查产物是否保留了要求的来源、内容、尺寸和状态。工具无法满足时，明确证据缺口并降低结论强度，不用无关视觉代替。

只有交互本身属于未决决定，且更轻的产物无法表达时才使用代码。比较色彩、排版或构图时不创建项目 Scaffold。

## 5. 呈现决定

每个 Probe 使用简短决策卡：

```text
Probe 名称：
验证的决定：
保持不变：
发生改变：
预期收益：
主要成本或风险：
证据或产物：
```

引导用户根据产品适配度和可接受风险选择，而不只依据个人喜好。从另一个 Probe 借用内容时，只命名一个具体维度，并保留一个主方向。

## 6. 停止条件

关键差异已经可见，用户能够选择或排除方向时停止。把选定结果写回 Art Direction Card、UI Brief 或 Interaction / IA Card，不把 Probe 调整扩展为无上限设计循环。
