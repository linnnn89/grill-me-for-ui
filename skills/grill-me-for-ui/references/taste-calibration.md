# Taste Calibration for UI Interviews

本文件用于把“高级、现代、有设计感、不要 AI 味”转化为可讨论、可执行、可验收的视觉决策。它不是一套统一审美，也不是用于机械禁止常见设计模式的清单。

## 设计立场

审美质量不是某种固定字体、配色或布局。它更接近以下能力：

- 根据产品、受众和使用情境读懂“这次应该是什么”；
- 在多个合理方向中选择一个清晰立场；
- 用少量一致规则形成辨识度；
- 克制无关装饰，避免模板化默认值；
- 在美感、任务效率、可信度、可访问性与性能之间作出可解释取舍。

## 从其他 Skill 借鉴什么

### Taste Skill

可借鉴：

- 先做 Brief Inference，再设计；
- 用表现力、动效、密度三个旋钮描述整体方向；
- 识别 LLM 常见默认模板并主动偏离；
- 重设计先审计现有页面；
- 实施前后设置 Pre-Flight 检查。

不要直接复制：

- 它主要面向 Landing、Portfolio 和品牌型重设计，不适合直接统治 Dashboard、数据表和多步骤产品 UI；
- 字体、颜色、Hero、Card 等“禁止项”只能作为偏差提醒，不是跨场景真理；
- 固定基线数字不能替代项目证据。

### Google Stitch `taste-design` 与 `DESIGN.md`

可借鉴：

- 将视觉气氛、颜色、排版、组件、布局、动效和反模式沉淀为持久设计契约；
- 设计 Token 提供准确值，设计说明解释为什么；
- 用统一文档让多个页面、多个 Agent 和多次迭代保持一致；
- 对颜色引用、对比度、缺失 Token 和章节结构进行自动检查。

不要直接复制：

- “所有活动组件必须永久循环动画”“所有多列布局在 768px 下无例外单列”“永远不用 Inter / 纯黑 / 居中 Hero”等规则过度绝对；
- 高级感不等于更强动效、更大圆角或更非对称；
- 医疗、金融、公共服务和高频工作台必须允许更克制、更稳定的设计。

## 一、先判断设计自由度

### 1. 界面类型

| 类型 | 首要价值 | 常见审美风险 |
|---|---|---|
| 产品 / 工作流 UI | 任务效率、反馈、稳定 | 为显得独特而干扰操作 |
| Dashboard / 数据工具 | 扫读、比较、密度、可信 | Card 堆砌、数据层级模糊 |
| 营销页 / 官网 | 品牌记忆、叙事、转化 | 套用通用 SaaS Hero 模板 |
| Portfolio / 创意展示 | 个性、节奏、作品呈现 | 动效压过内容、过度实验 |
| 内容 / Editorial | 阅读、排版、内容气质 | 只用“大衬线 + 米色”冒充编辑感 |
| 消费型移动端 | 触感、情绪、高频任务 | 把展示稿效果带入长期使用 |
| 设计系统 | 一致性、组合能力、扩展 | 规则过多、例外无治理 |
| 受监管 / 信任优先 | 可理解、可追溯、无障碍 | 将克制误解为平庸模板 |

### 2. 四个约束信号

在讨论视觉前，读取：

- **任务频率**：每天数十次操作，还是偶尔浏览一次；
- **错误代价**：误点、误读或误判会造成什么后果；
- **信任要求**：用户是否需要理解来源、状态和限制；
- **品牌表达需求**：品牌是否必须在短时间内留下记忆。

任务越频繁、错误代价越高，设计越应稳定、可预测；品牌表达越重要、浏览越低频，可允许更高视觉表达度。

## 二、形成 Design Read

Design Read 应简短回答：

```text
这是一个[界面类型]，面向[受众]，帮助他们完成[任务]；
视觉语言应偏向[气质 / 设计家族]，主要依靠[构图 / 排版 / 图像 / 材质]表达；
由于[信任、使用频率、品牌、设备或无障碍约束]，应避免[主要风险]。
```

好的 Design Read 会排除一些方向。例如：

- 医学研究 Dashboard：精密、清晰、层级稳定；允许高密度，但避免“科技霓虹”和无意义动效；
- 创意工作室官网：可接受非对称和强排版，但作品必须仍是视觉主角；
- 消费金融 App：需要亲和与安全感，但不能用过度可爱的反馈弱化金额和风险信息。

## 三、三项审美旋钮

### `EXPRESSION`：视觉表达度

- 1–3：高度克制、熟悉、信任优先；
- 4–6：有明确性格，但仍以任务为中心；
- 7–8：品牌与视觉叙事显著；
- 9–10：实验性和艺术表达主导，仅适合少数低风险场景。

### `MOTION`：动效强度

- 1–2：仅状态反馈；
- 3–5：页面切换、展开和空间关系动画；
- 6–8：有编排的进入、滚动或叙事动效；
- 9–10：动画成为核心体验，需要明确性能、可访问性和降级方案。

### `DENSITY`：信息密度

- 1–3：画廊、品牌展示、沉浸阅读；
- 4–6：普通产品和消费应用；
- 7–8：专业工具、Dashboard、表格；
- 9–10：高熟练度驾驶舱，需要强层级、快捷操作和定制能力。

数字只用于校准，不代表质量。Agent 应先给出推断区间，并说明原因；只有存在真实分歧时才询问用户。

### 情境起点，不是硬预设

| 场景 | EXPRESSION | MOTION | DENSITY |
|---|---:|---:|---:|
| 医疗 / 公共服务工作流 | 2–4 | 1–3 | 5–8 |
| B2B SaaS 产品界面 | 3–6 | 2–5 | 5–8 |
| 数据分析 Dashboard | 3–5 | 1–4 | 7–9 |
| 主流 SaaS Landing | 5–8 | 3–7 | 3–5 |
| 创意机构 / Portfolio | 7–9 | 5–8 | 2–5 |
| Editorial / 内容品牌 | 5–8 | 2–5 | 2–5 |
| 消费型移动端 | 4–7 | 3–6 | 4–7 |

## 四、写出视觉主张

视觉主张不是风格标签，而是设计决策句：

```text
以[一种主导方式]建立[目标感受]，
用[一种强调方式]突出[最重要内容或动作]，
其余元素保持[克制原则]，避免[最可能的模板化风险]。
```

示例：

> 以紧凑的网格与清晰数字排版建立研究工具的精密感，用单一高对比强调色标记可操作状态；弱化卡片表面和装饰动效，避免把结果页做成通用 SaaS 指标卡墙。

## 五、选择一个标志性设计动作

一个页面或流程通常只需要一个主要记忆点。

可能的设计动作：

- 构图：非对称首屏、固定侧栏与流动内容、列表与详情连续空间；
- 排版：独特但稳定的标题比例、数字排版、章节节奏；
- 图像：统一裁切、镜头语言、插画系统或图表风格；
- 材质：明确的边框、层次、透明度或纸张感；
- 交互：一处解释空间关系或状态因果的动效；
- 秩序：极强的扫读层级和信息压缩本身。

检查：

1. 它是否服务产品和受众；
2. 用户是否能在数秒内感知；
3. 去掉它后页面是否更像通用模板；
4. 它是否会损害任务、性能或可访问性；
5. 是否有第二、第三个“亮点”正在争夺注意力。

## 六、拆解参考，而不是复制参考

| 维度 | 观察内容 | 需要确认的取舍 |
|---|---|---|
| 构图 | 对齐、分栏、重心、留白 | 保留结构还是只借节奏 |
| 密度 | 同屏信息量、折叠方式 | 更适合浏览还是操作 |
| 排版 | 字体性格、层级、行长 | 借气质还是借具体字体 |
| 色彩 | 中性色、强调色、语义色 | 品牌色能否承担同一角色 |
| 深度 | Card、边框、阴影、透明 | 层级是否真的需要表面容器 |
| 图像 | 实拍、插画、图标、图表 | 当前是否有同质量素材 |
| 动效 | 触发、时长、空间因果 | 是否帮助理解或只作装饰 |
| 内容 | 标题长度、证据、CTA | 参考结构是否匹配真实内容 |

不要把参考品牌的识别性元素直接复制到无关产品，也不要假装“像 Apple / Linear / Notion”已经构成完整方向。

## 七、情境化 Anti-Slop Gate

在结束访谈前检查：

### 1. 产品特异性

- 隐去 Logo 后，这个界面是否仍能看出它服务什么产品和用户；
- 内容、数据和操作是否真实驱动布局；
- 是否出现随便替换文案也成立的模板区块。

### 2. 单一视觉主导

- 第一眼重点是否唯一；
- 是否同时堆叠渐变、玻璃、噪点、Bento、大标题和复杂动画；
- 标志性动作是否被次级装饰稀释。

### 3. 一致性

- 圆角、边框、阴影和表面层级是否遵循同一规则；
- 强调色、语义色和状态色是否角色清晰；
- 字体和字号是否构成稳定层级，而不是每个区块重新设计。

### 4. 组件必要性

- Card 是否表达真实分组或层级；
- Eyebrow、Badge、Chip、Tooltip 是否承担信息功能；
- 相同意图是否使用一致 CTA 文案；
- 是否存在为了“填满页面”创建的指标、客户 Logo 或功能卡。

### 5. 动效因果

- 动画是否解释进入、离开、展开、排序、进度或空间关系；
- 高频操作是否足够快；
- 是否有持续循环动画无理由争夺注意力；
- reduced motion 和低性能设备如何降级。

### 6. 内容与可信度

- 不生成用户未提供的指标、评价、客户、奖项和统计；
- 示例内容明确标记为 Placeholder；
- 错误、权限、数据更新时间和 AI 生成内容是否透明。

### 7. 响应式与可访问性

- 移动端是否保留核心任务，而不是机械单列；
- 表格、图表和复杂布局是否有明确小屏策略；
- 对比度、Focus、键盘、点击目标和内容增长是否满足边界。

## 八、不要使用绝对审美禁令

以下表达只能作为偏差提醒，不能直接写成全局规则：

- “禁止 Inter / 衬线 / 纯黑”；
- “禁止居中 Hero / 三列卡片 / Card”；
- “必须只有一个强调色”；
- “必须非对称”；
- “所有页面都要强动效”；
- “所有移动端都必须单列”；
- “大圆角或毛玻璃才高级”。

正确做法是询问或推断：这个选择在当前产品中是否有功能、品牌或内容依据。

## 九、适合访谈的审美问题

一次只选择一个：

- 这页更应像“稳定高效的工具”，还是“具有强烈品牌记忆的展示界面”？
- 用户第一眼应先感到“可信和清楚”，还是“新鲜和有冲击力”？
- 参考页面中真正想借的是构图、排版、密度、颜色还是动效？
- 视觉重点主要靠排版和留白，还是靠图像和材质？
- 这页是否需要一个明显记忆点；若需要，它最适合来自构图、排版、图像还是交互？
- 当前页面最像 AI 模板的地方，是卡片结构、颜色、文案、字体还是区块节奏？

每个问题都应附带基于当前证据的推荐，而不是让用户凭空设计。
