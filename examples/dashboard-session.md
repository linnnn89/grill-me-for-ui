# Example Session: Medical Research Dashboard

> **仅供人类阅读与离线评估。正常 Agent 运行时禁止加载本示例。**

本示例展示问题风格和分支依赖，不是固定脚本。

## 用户输入

> 我想做一个医学科研数据 Dashboard，先 grill me，别急着写代码。

## Agent 启动

```text
Surface：Operate；依据是用户需要在界面中筛选、比较、解释并导出研究结果
Baseline：无可复用基线；当前没有代码、截图、Token 或已确认设计决定
Scenario：Greenfield；依据是新建一个 Dashboard，且没有旧视觉身份需要保留或替换
Scope / Tier：一个 Dashboard 的核心流程；具体结构深度待对象与任务确认
Depth / Action：shape；先定义任务、对象与结构，不进入实现
Reference / Stop：interview-map.md；核心流程和方向足以形成 UI Brief 时停止
```

> 我理解这是一个供研究者查看研究样本、模型结果和导出数据的 Dashboard。当前没有代码或截图可检查，因此先梳理核心任务。最上游的不确定性是：这个页面主要用于快速监测，还是用于深入分析；两者会改变对象关系、信息密度和后续交互。

### 问题 1 · 主要任务

这个 Dashboard 最常被打开来完成哪一件事？

**为什么现在要决定：** 它会决定首屏展示 KPI、分析图表，还是可操作的数据表。

**可选方向：**
A. 快速掌握项目状态和异常
B. 深入筛选、比较和解释研究结果
C. 管理数据、运行分析和导出

**我的推荐：** B — “科研数据 Dashboard”通常需要支持比较与解释；状态概览可以作为首屏摘要，但不应取代分析工作区。

回复 A/B/C，或直接说你的方案。

## 用户回答

> 主要是 B，但也需要导出结果。

## Agent 记录并继续

**已确认：** 主任务是筛选、比较和解释结果，导出属于重要次级动作。
**影响：** 首屏应优先支持筛选和数据阅读，导出不应与主分析动作争夺视觉优先级。

### 问题 2 · 用户熟练度

主要用户是熟悉统计术语的研究者，还是需要解释提示的普通临床人员？

**为什么现在要决定：** 它会影响术语密度、默认展开的信息和 Tooltip / 帮助内容。

**可选方向：**
A. 统计研究者为主，界面可以紧凑且专业
B. 临床人员为主，需要更强解释和引导
C. 两类用户都支持，以分层呈现兼顾

**我的推荐：** C — 首层保留临床可读摘要，详细统计量和模型参数按需展开，避免同时牺牲效率和可理解性。

## 用户回答

> C。

## 条件阶段：Interaction / IA

前两题确认这是一个 Operate 表面，但“结果”究竟属于哪个研究对象、用户从哪里进入分析、导出如何继承上下文仍会改变页面结构，因此临时进入 Interaction / IA。

```text
Stage Contract：interview-map → Interaction / IA → interview-map；将紧凑 Interaction / IA Card 写回 UI Brief 的“任务与结构”部分
```

### 问题 3 · 核心对象

用户实际在什么对象之间工作：研究项目、数据集、分析运行、结果，还是导出文件？其中哪个对象必须始终保持当前上下文？

**为什么现在要决定：** 如果“结果”属于一次分析运行，筛选、比较和导出都应继承该运行；如果直接属于项目，导航和权限边界会完全不同。

**可选方向：**
A. 项目 → 数据集 → 分析运行 → 结果 / 导出
B. 项目 → 结果，分析运行只作为后台历史
C. 以数据集为中心，项目只是分组标签

**我的推荐：** A — 它最容易解释结果来源、参数版本和可复现导出，也能避免用户把不同运行的结果误认为同一分析。

### 问题 4 · 进入路径与上下文

用户通常从项目进入最近一次分析，还是从全局结果列表跨项目搜索？切换模块时必须保留哪些上下文？

推荐假设：默认从项目进入当前分析运行；跨项目搜索作为辅助入口。切换样本特征、模型结果和诊断时保留项目、数据集版本、分析运行与筛选条件。

### 问题 5 · 权限、状态与恢复

谁可以启动新分析、修改筛选、查看受限变量和导出？分析运行中、失败或结果过期时，用户最不能丢失什么？

推荐假设：浏览与配置分权；运行状态持续可见。失败时保留分析参数、筛选、当前位置和最近成功结果，允许局部重试，不清空整个工作区。

## Interaction / IA Card 示例

- 核心层级：项目 → 数据集版本 → 分析运行 → 结果；导出是当前运行的产物。
- 主要任务：在一个运行上下文中筛选、比较和解释结果；导出继承当前筛选与版本信息。
- 导航原则：项目和当前运行是稳定上下文；样本特征、模型结果与诊断是同层工作区。
- 权限原则：查看、配置、运行和导出分别受控，不用“按钮是否出现”代替权限解释。
- 关键状态：未运行、运行中、成功、失败、结果过期；恢复时保留参数、筛选和最近成功结果。
- 未决结构：同层工作区用 Tabs 还是其他局部导航；结果详情用 Drawer 还是独立页面。

这些关系已经能用文字排除“把所有内容平铺在一个页面”和“以导出文件为中心”的方案，不需要 Visual Probe。Interaction / IA 条件阶段结束，携带上面的 Card 返回 `interview-map`。

## 返回主阶段后的关键问题示意

### 问题 6 · 第一眼信息

在首屏只能固定展示三项内容时，哪三项最重要？

推荐假设：样本量、当前结局发生率、主要模型效应量；数据质量警告在存在异常时提升为 Alert。

### 问题 7 · 页面结构

项目、数据集版本和当前分析运行应放在稳定侧栏或上下文栏；样本特征、模型结果和诊断应如何组织？

推荐假设：Sidebar 管理项目与运行上下文，分析工作区内用 Tabs 切换样本特征、模型结果和诊断；导出作为当前运行的次级动作，不与这些同层对象并列。

### 问题 8 · 详情方式

点击表格中的模型或亚组后，是进入独立详情页，还是从右侧打开 Drawer？

推荐假设：使用 Drawer 保留筛选和表格上下文；只有需要分享固定链接或展示大量图表时才进入详情页。

### 问题 9 · 手机端策略

手机端是完整分析工具，还是只读概览和告警？

推荐假设：手机端保留概览、关键结果和轻量筛选；复杂表格与模型配置明确引导到桌面端，避免把桌面工作台机械压缩。

### 问题 10 · 视觉方向

界面更偏“严谨紧凑的科研工具”，还是“宽松易读的临床产品”？

推荐假设：平衡密度；表格和筛选区紧凑，结果摘要和解释区留白更宽，语义色只用于状态和效应方向。

## 共享理解摘要示例

- 主要用户包括统计研究者和临床人员，采用分层信息设计。
- 核心任务是筛选、比较和解释结果；导出是重要次级动作。
- 核心对象为项目、数据集版本、分析运行和结果；导出是当前运行的产物。
- 使用 Sidebar 保持项目与运行上下文，分析页内使用 Tabs 管理同层工作区。
- 首屏展示样本量、结局发生率和主要效应量；异常数据质量使用持续 Alert。
- 表格详情优先使用 Drawer 保留上下文；复杂详情可有独立可分享页面。
- 手机端定位为概览和轻量查看，不承诺完整复杂分析。
- 权限区分查看、配置、运行和导出；请求失败时保留参数、筛选、位置和最近成功结果。
- 视觉为严谨、平衡密度、低装饰；状态色有明确语义。

## 示例中的关键做法

- 启动时先给出可解释的 Router Trace；
- 每次只推进一个决策主题，不把无关问题堆在同一轮；
- 每题说明为什么影响后续；
- 给出推荐，但保留用户决定权；
- 先确定任务和核心对象，再讨论 Tabs、Drawer 等组件形式；
- IA 只作为条件阶段，产出紧凑 Card 后返回直接调用的主阶段；
- 文字证据足够时明确不使用 Visual Probe；
- 覆盖移动端和失败状态；
- 在确认基线前不实施。
